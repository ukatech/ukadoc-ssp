# 設定：開発/その他

このページでは右クリックメニューの「設定」サブメニューにある項目「本体設定」で開くダイアログの、「開発/その他」ページについて解説しています。

このページでは開発用やその他細かい設定を行います。

!!! tip "ヒント"

    この設定は「[一般](ippan.md)」の設定で、「開発者用機能を有効にする」をONにしないと表示されません。

開発者用、その他特殊な場合に設定する必要がありますが、その他の場合はすべて標準設定で問題ありません。<br>
<strong>特に必要のある場合以外は設定を変えないでください。</strong>

## 各項目の解説

- **FMO名を変更する**<br>
  現在起動中のゴーストをリストアップするFMOの名前を変更します。<br>
  通常は標準のSakuraのままで問題ありません。
- **フォルダをドロップした際に更新ファイルやNARを作成**<br>
  ゴーストにフォルダをドラッグ＆ドロップした際の動作を決定します。<br>
  開発時はONにしておくと、ゴーストに通知するか開発系のコマンドを実行するかの動作を選択できるようになります。
- **ネットワーク更新時に旧ファイルを残す**<br>
  ネットワーク更新で一時的に作成したファイルを、削除しないで保存しておきます。<br>
  ネットワーク更新の際に起こった問題などを追跡するために使用することが出来ます。
- **読み取り専用属性ファイルは更新対象にしない**<br>
  ネットワーク更新の対象になっているファイルに読み取り専用属性がついている場合、更新せずにそのまま残しておきます。
- **サーフィスが存在しない時に非表示とする**<br>
  スクリプトで指定されたサーフィスが存在しない時に、ゴーストのウィンドウを消去します（通常はデフォルトサーフィスが表示）。<br>
  ゴーストのスクリプトの不具合の検証用途などに利用できます。
- **Materiaが起動しているように見せかける**<br>
  Mutex "sakura" を作成し、Materiaが起動しているかのようにふるまいます。<br>
  Materiaでしか動作しない設計となっているソフトが動作する可能性があります。
- **Vanish（アンインストール）実行を抑制**<br>
  絶対にVanish（アンインストール）を実行できない状態にします。<br>
  ゴースト開発中等に誤ってVanishを実行してしまうのを防ぐ等に利用できます。　
- **複数起動ロックを解除**<br>
  通常SSPは1マシンに1つしか起動できないようになっていますが、開発用とその他用に分けたい場合など、複数起動したい場合にこのロックを解除してください。<br>
  ただし、SSP自体は複数起動を前提とした設計になっていませんので、多少不具合が起こる可能性があります。<br>
  また、NARファイルを関連付けしている場合、NARを開いてのインストール実行ができなくなります（ドラッグ＆ドロップは利用可能）。
- **利用可能な場合は更新にバージョン管理ツールを使う**<br>
  ゴーストの管理にバージョン管理ツールが使われている場合は、通常のネットワーク更新の代わりに、それを起動して「更新」処理を行います。
- **\[XXX\]レベル以上のエラー発生を通知**<br>
  選択したレベル以上のエラーが発生した際に、タスクトレイアイコンからバルーンを表示します。<br>
  ゴースト開発者は、開発中NOTICEか少なくともWARNING以上を通知することが推奨されます。<br>
  通知レベルの意味については「[スクリプトログ](../dev/scriptlog.md#エラーログ)」のページを参照してください。
- **例外ハンドラを使う**<br>
  デバッグに協力していただける方や、ゴースト開発者はOFFにしておくと、メモリへのアクセス違反等で「ちゃんと落ちる」ようになります。<br>
  あまり頻繁にSSPが落ちるような場合はONにするといくらか軽減するかもしれませんが、開発中は非推奨です。
- **自動更新の際にテスト版も対象にする**<br>
  更新チェックの際の対象をテスト版まで広げます。次期メジャーバージョンアップのテスト版などを自動で入手できます。

### 更新定義ファイル

updates2.dauとupdates.txtのどちらか、あるいは両方を出力するか設定します。

- **常にUTF-8文字コードを使用する**<br>
  多バイト文字を含むファイル名を使用した時に、必ずUTF-8でファイル名を出力します<br>
  文字化けを根本的に解決することができ、最近のSSPでは文字コードを自動認識しますので問題ありませんが、古い環境で互換性の問題が発生するかもしれません。
- **ファイルのハッシュ値計算処理キャッシュ**<br>
  古い更新定義ファイル内のハッシュ値計算結果をなるべく再利用します。<br>
  大量のファイルがある時に多少更新定義の生成が速くなる可能性がある代わりに、信頼性は低下します。

### NAR作成位置

NAR作成機能でNARファイルを出力するパスを設定します。

- **毎回指定**<br>
  毎回作成先とそのファイル名を指定します。
- **フォルダと同じ**<br>
  NARを作成するゴーストのフォルダと同じ場所に作成するようにします。
- **指定したフォルダ**<br>
  常に指定したフォルダの中に作成するようにします。

## 下部のボタン

- **ヘルプ**<br>
  本体設定ダイアログの、設定中のページのヘルプ（つまりこのページ）を開きます。<br>
  ダイアログ右上の「？」マークも同様です。
- **閉じる**<br>
  本体設定ダイアログを閉じます。<br>
  ダイアログ右上の「×」マークも同様です。
