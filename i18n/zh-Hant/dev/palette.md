# 開發者說明：開發用調色盤

這個對話方塊彙集了開發時實用的設定開關和工具啟動按鈕。<br>
除了人格之外，也適用於對話方塊和外殼的開發。

此外，開發用調色盤的設定會以各人格為單位管理。

## 核取方塊

### 顯示碰撞判定

勾選後，會顯示區域及其判定名稱。<br>
半勾選時則會隱藏判定名稱。當區域線條和判定名稱重疊而難以辨識時，可以使用這個選項。<br>
查看線條的重疊情形，也能大致判斷碰撞判定的上下順序（位於下方的區域無法觸碰）。

圖片中的範例只有矩形判定區域，當然也支援多邊形或圓形等判定形狀。

### 對話方塊測試模式

開啟後，會在 `\1`・`\0` 對話方塊上顯示測試資訊。<br>
除了可透過顯示的數字確認橫向與縱向的顯示字數外，也會顯示以下項目，可用於調整位置等。

- 用於顯示更新進度的計數器
- 更新時播放的循環動畫（使用 `online*.png`）
- 用於捲動的箭頭（arrow0/1.png）
- SSTP 標記
- SSTP 訊息

### SERIKO 延遲調整

開啟後會顯示輸入框，可用百分比調整外殼動畫的延遲。<br>
設為 100% 時，會依照設定的延遲逐格播放。<br>
關閉後，設定便會失效。<br>
可用於檢查快速且影格數較多的動畫中是否有異常影格等。

### 僅檢查更新

開啟後執行線上更新時，雖然會觸發更新事件，但實際上不會覆寫檔案。<br>
除了可避免因誤執行更新而覆寫開發中的檔案，也可用於測試更新事件的動作等。

### 變更 SHIORI 的 Sender

開啟後會顯示輸入框，可變更 SSP 向 SHIORI 自稱的傳送者名稱。<br>
關閉後，設定便會失效。

### 啟用 SHIORI 呼叫記錄

```
=====send=====
GET SHIORI/3.0
Charset: Shift_JIS
Sender: SSP
SecurityLevel: local
ID: OnSecondChange
Reference0: 193
Reference1: 0
Reference2: 0
Reference3: 1
Reference4: 0


=====response=====
SHIORI/3.0 204 No Content
Charset: Shift_JIS
```

開啟後，會記錄 SSP 與 SHIORI 之間的通訊，並輸出至人格的 master 資料夾，檔名為 `ssp_SHIORI_log.txt`。<br>
請注意不要將記錄檔包含在更新檔案中。<br>
此外，若一直開啟記錄功能而未關閉，檔案可能會在不知不覺中變得相當大，請多加留意。

### 啟用 SHIORI 內部記錄功能

啟用或停用的資訊會透過 SHIORI Event「`enable_log`」通知。<br>
SHIORI 端可讀取這項資訊，藉此控制 SHIORI 本身的記錄功能是否啟用。

### 啟用 SHIORI 偵錯功能

開啟後，便會啟用由 SHIORIEcho 等外部來源觸發的偵錯事件。<br>
若未開啟，基於安全性考量，這些事件會被忽略（一般 SHIORI 端也會設定為忽略這些事件）。<br>
部分 SHIORI 偵錯工具必須開啟此選項才能運作，請留意（例如：華和梨的らふらんす・幸水）。

### 停用自動切換

開啟後，SSP 的[自動切換功能](../config/ghost.md)將不適用於該人格。<br>
開發期間通常會讓人格一直保持顯示，因此這個選項可避免人格在這種情況下自行切換。

### 停用自動檢查

開啟後，該人格執行期間，即使偏好設定中的選項已開啟，也不會自動進行 RSS／線上新聞感應及電子郵件檢查。

### 停用自動更新

開啟後，[自動更新功能](../config/ghost.md)將不適用於該人格。<br>
可避免開發中的人格資料因更新而遭到覆寫。

### 不因 `\-` 標籤而結束

開啟後，即使該人格正在執行的腳本中出現 `\-`（結束人格的指令），也會忽略這個指令。<br>
除了可避免開發中的人格意外結束，也可用於測試包含 `\-` 的談話。

## 按鈕

### 輸入腳本

會開啟 SEND 方塊，輸入 Sakura Script 後即可直接執行。<br>
請注意，這裡不能輸入各 SHIORI 字典所使用的語法。

### 外觀測試

開啟可用於對外殼進行各種測試的對話方塊。

對話方塊中央有 4 個清單。<br>
最左側標示 **WND** 的清單用來選擇要操作的範圍（`\0`、`\1`、`\p[2]`...）。<br>
由左數來第二個標示 **Surface** 的清單會列出已辨識的外觀。在此選取外觀，即可切換 WND 清單中所選範圍的顯示。清單上方 Surface 旁的數字表示（surfaces.txt 中定義的外觀數／包含未定義但只有圖片的外觀在內的總數）。<br>
由右數來第二個標示 **ID** 的清單會顯示所選範圍中定義的動畫 ID。選取後，若目前顯示的外觀有該 ID 的定義，就會執行該 ID 的動畫。清單上方 ID 旁的數字表示總數。<br>
最右側的 **COL** 清單會顯示所選 Surface 中定義的碰撞判定 ID 及其名稱。清單上方 COL 旁的數字表示總數。

按下左下方的「▼」按鈕會開啟功能選單。<br>
目前只能選擇「Copy Surface List」。選擇後，已辨識的所有外觀會以「`surface**`」的格式逐行列出，並複製到剪貼簿。

旁邊會列出已載入的圖片檔案數量及總容量。

再旁邊有 3 個核取方塊。<br>
開啟 **Sort** 時，Surface 清單會依 ID 遞增排列，而非依照描述順序排列。<br>
開啟 **Copy** 時，選取外觀後，會將切換至該外觀的腳本複製到剪貼簿（例如將 `\0` 切換為 surface1 時，腳本為 `\0\s[1]`）。<br>

### 顯示錯誤記錄

顯示已通知錯誤的歷程清單。<br>
詳細資訊請參閱「[腳本記錄](scriptlog.md#エラーログ)」頁面。

### 虛擬變更目前時間

設定時間後，SSP 所識別的目前日期與時間會以虛擬方式替換為設定的日期與時間。<br>
這樣一來，即使不實際修改 OS 時間，也能測試人格因日期與時間不同而產生的動作。

**Present Time** 是目前在 SSP 中設定的虛擬日期與時間。<br>
**System Time** 是 OS 內部的實際日期與時間。<br>
按下 **Apply** 按鈕，會將輸入框中的日期與時間設為虛擬時間。<br>
按下 **Reset** 按鈕，會將虛擬時間還原為 System Time。

### SERIKO Inspector

以樹狀檢視方式顯示外殼的定義。<br>
各 surfaceID 會分別顯示 element、collision、animation 節點（分支），再依照各節點所擁有的 ID 分出子節點，並繼續顯示其組成元素……如此一來，就能直覺地掌握外殼定義的結構。

按下右下方的 **Dump** 按鈕，會開啟檔案儲存對話方塊，並輸出以定位字元縮排呈現結構的文字檔。

### 重新載入

重新載入從選單中選取的項目。<br>
開發期間修改、追加或刪除檔案時，請使用此功能。

### 開啟／執行

開啟或執行從選單中選取的項目。

- **BALLOON**<br>
  **GHOST**<br>
  **SHELL**<br>
  分別開啟目前使用中的對話方塊、人格和外殼資料夾。<br>
  開發期間經常需要開啟這些資料夾，可在這種情況下使用。
- **SHIORI LOG**<br>
  開啟由上方「[啟用 SHIORI 呼叫記錄](#shiori呼出ログ有効)」建立的記錄檔。<br>
  若記錄檔尚未建立，便無法選取。
- **VCS Uppdate**<br>
  **VCS Commit**<br>
  **VCS Log**<br>
  **VCS Revert**<br>
  **VCS Export**<br>
  可在此操作於偏好設定的「[外部應用程式](../config/extprog.md)」中設定的版本控制工具。
- **UPDATE EVENT/NORMAL**<br>
  **UPDATE EVENT/NONE**<br>
  **UPDATE EVENT/ERROR**<br>
  **UPDATE EVENT/NORMAL GBALLOON**<br>
  即使沒有實際更新，也能使用虛構的更新內容測試更新事件的動作。<br>
  **NORMAL** 會模擬找到更新檔案並順利完成更新時的動作。<br>
  **NONE** 會模擬找不到更新檔案時的動作。<br>
  **ERROR** 會模擬因錯誤而中斷更新（md5 不一致）時的動作。<br>
  **NORMAL GBALLOON** 會模擬依照[偏好設定](../config/ghost.md)，更新時一併進行的外殼與對話方塊更新檢查。
