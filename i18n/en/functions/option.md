# Startup options

You can start ssp.exe with the following options (switches).

## What are startup options?

They are a way to change settings when starting Windows software.<br>
For more information, search for terms such as runtime options, command-line options, and startup options.

## How to use them

There are several ways to use them.<br>
For example, you can use them from the Command Prompt or the Run dialog.<br>
Here is how to create a shortcut for a specific option.

1. Create a shortcut to ssp.exe.<br>
   Example: Right-click ssp.exe→Create shortcut
2. Open the properties of the shortcut you created.<br>
   Example: Right-click the shortcut→Properties
3. Check that the path to ssp.exe is in the Target field, then enclose the entire path in double quotes ("").
4. Add a space after the quoted path, then enter a startup option from the list below.<br>
   Example: "C:/User/Document/略/SSP/ssp.exe" --random
5. Click OK to close the properties, and give the shortcut a descriptive name.<br>
   Example: SSP-Random startup
6. Run the shortcut to start SSP with the option applied, rather than starting ssp.exe normally.

## Options

The `--オプション名` format is recommended for each option. Short options in the `/x` and `-x` formats are still available for backward compatibility.

For options that take a value, separate the option name and value with a space, as in `--オプション名 値`. If the value contains spaces, enclose it in double quotes ("").

From 2.8.97 onward, the `--オプション名=値` format is also accepted (example: `--sstp-listen=9900`). This page primarily uses the space-separated format. The `=` format cannot be used with short options in the `/x` format.

### --option options

Multiple --option values can be specified as a comma-separated list (example: `--option bootunlock,standalone`).

| Switch | Function |
|---|---|
| --option nobootcheck<br>(Legacy: /o nobootcheck) | Disable abnormal termination checks |
| --option layered<br>(Legacy: /o layered) | Enable translucent windows |
| --option region<br>(Legacy: /o region) | Disable translucent windows (region mode) |
| --option bootunlock<br>(Legacy: /o bootunlock) | Skip the multiple-instance check |
| --option standalone<br>(Legacy: /o standalone) | If SSP.exe is already running, disable the mechanism that delegates operations such as installation and starting ghosts to the running instance, and always perform those operations in the new instance.<br>Combine this with skipping the multiple-instance check, as in --option bootunlock,standalone, to run multiple instances of SSP.exe without any warnings. |
| --option kiosk<br>(Legacy: /o kiosk) | Enable KIOSK mode. It behaves as follows: \[2.6.54 onwards\]<br>Enables --option bootunlock,standalone<br>Always sets alignmenttodesktop to free<br>Does not accept mouse or keyboard input<br>Does not interfere with the multiple-instance check in any way<br>Does not display notification area or taskbar icons<br>Does not save ghost or shell settings managed by SSP<br>Does not display the startup window<br>Does not show error notifications |
| --option readonly<br>(Legacy: /o readonly) | Enable read-only mode. \[2.8.96 onwards\]<br>Starts without making any persistent changes to the user environment. Use this to try SSP without altering settings, or to run SSP temporarily on someone else's PC.<br>On-screen behavior and interactions with ghosts work as usual; unlike KIOSK mode, input and display are not restricted. It is independent of KIOSK mode and can be combined with it, as in --option kiosk,readonly.<br><br>It behaves as follows:<br>Enables --option bootunlock,standalone (because delegating operations to a running instance of SSP would allow that instance to write settings)<br>Does not interfere with the multiple-instance check in any way<br>Does not save Preferences or ghost, shell, balloon, or plugin settings<br>Does not save startup history, usage statistics, caches, cookies, vanish records, SSTP settings, POP settings, or Ukagaka messenger information and logs<br>Does not save Calendar schedules (schedule.ics)<br>Does not share save data (neither exports it to the cloud nor restores it from the cloud to the local PC)<br>Does not write to the registry, associate files, create shortcuts, register jump lists, or add items to Recent Items<br>Does not change the desktop wallpaper or background color<br>Does not empty the Recycle Bin<br>Does not delete the ghost's folder when it vanishes<br>Does not automatically update SSP, ghosts, balloons, plugins, or language resources. Does not perform manual network updates or install NAR files either<br>Does not install `initial_install.nar`<br>Does not perform NTP time sync via SNTP<br><br>Settings can still be changed as usual, but they are not written back to files on exit and will not carry over to the next startup.<br>Temporary files required for operation (in the temporary folder) are still created as usual and discarded on exit. |
| --option dontloadmodule<br>(Legacy: /o dontloadmodule) | Do not load SHIORI/MAKOTO/PLUGIN/HEADLINE/CALENDAR components |
| --option dpiaware<br>(Legacy: /o dpiaware) | Start with DPI Awareness Mode set to Per-Monitor V2 |
| --option callghost<br>(Legacy: /o callghost) | When used with --install, automatically start the ghost after installation. |
| --option deletesource<br>(Legacy: /o deletesource) | When used with --install, delete the NAR after a successful installation. |

### General options

| Switch | Function |
|---|---|
| --fmo-name FMO name<br>(formerly: /f FMO name) | Forces the specified FMO name to be used for writing. |
| --random<br>(formerly: /r) | Starts a random ghost regardless of settings. |
| --ghost folder name/ghost name<br>(formerly: /g folder name/ghost name) | Starts the specified ghost. Separate names with spaces to start multiple ghosts. From 2.9.35 onward, you can also specify the ghost's UUID (the property system's `uuid`, in a form such as `R5dVNluBvKjtQqjP0dAuoA==`) instead of the folder name/ghost name. When specified at SSP startup, the first specified ghost is started as the first ghost pair.<br>From 2.8.99 onward, if an absolute path to a ghost folder is specified at SSP startup (for example, `ssp.exe --ghost "C:\Users\user\Desktop\myGhost"`), and that ghost is not in a load folder, its parent folder (`C:\Users\user\Desktop\` in this example) is temporarily added to the ghost load folders for that session only. This applies only to folders containing `ghost\master\descript.txt`.<br>Temporarily added folders are not saved in the settings. They appear as "(temporary)" on the folder settings screen and cannot be edited or deleted there. They are also not offered as ghost installation destinations. If the same folder is explicitly added through the folder settings screen, it is saved as a normal load folder.<br>This process does not take place if SSP is already running (when the specification is passed to the running instance). |
| --help<br>(formerly: /?) | Opens the startup options help page in a browser. |
| --help filename<br>(formerly: /? filename) | Opens the help page for the specified filename in a browser. |
| --ukagaka-link x-ukagaka-link:URL<br>(formerly: /m x-ukagaka-link:URL) | Performs the same action as opening an x-ukagaka-link:URL. When specified at SSP startup, it waits until the first ghost pair has started before executing. |
| --install NAR filename<br>(formerly: /i NAR filename) | Installs a NAR. If SSP is already running, the running instance handles the installation; otherwise, this instance performs the installation and then continues startup.<br>Specify multiple NARs separated by spaces to install them in sequence.<br>This also works if the receiving SSP instance is displaying a warning dialog saying that no ghosts are installed (the "Please do something" dialog).<br>In that case, if --option callghost is also specified, the warning dialog's button to continue startup is automatically pressed. |
| --ssf SSF filename<br>(formerly: /s SSF filename) | Runs an [SSF file](https://emily.shillest.net/specwiki/?SSP/%E4%BB%95%E6%A7%98%E6%9B%B8/SSF%E3%83%95%E3%82%A1%E3%82%A4%E3%83%AB). When specified at SSP startup, it waits until the first ghost pair has started before executing. |
| --windowmode mode \[optional\] | From 2.8.78 onward, starts in the experimental "[Window mode](windowmode.md)". Ghosts run inside a window treated as a virtual screen, making capture operations easier and preventing effects on the entire desktop.<br>From 2.8.86 onward, a mode can be specified. The available modes are listed below. If omitted, the previous setting is used (the default is shared).<br>shared: Groups all running ghosts in one window.<br>perghost: Provides one window per ghost.<br>From 2.8.86 onward, the Window mode state is saved as a setting, so SSP starts in the previous state even without this option. To turn it off, use "Settings" in the right-click menu or "Streaming" in Preferences. |
| --sstp-listen listen address | Starts SSP with a temporary SSTP server listen address. \[2.8.97 onward\]<br>The saved SSTP server listen settings are not loaded; SSP listens only on the specified addresses.<br>The listen settings for this session are not saved. The SSTP server list in Preferences is read-only, and entries cannot be added, deleted, or edited (only "Retry Listen" is available).<br>This is intended for use with --option readonly to run a test instance of SSP that does not interfere with other running instances.<br><br>Multiple listen addresses can be specified, separated by commas. The formats are as follows.<br>Port number: Listens on the IPv4 and IPv6 loopback addresses (127.0.0.1 and ::1). Example: 9801<br>localhost:port number: Same as specifying only a port number.<br>IPv4 address:port number: Listens only on the specified address. Specify 0.0.0.0 to listen on all IPv4 interfaces. Example: 192.168.0.5:9801<br>\[IPv6 address\]:port number: Enclose the IPv6 address in \[\]. Specify \[::\] to listen on all IPv6 interfaces. Example: \[::1\]:9801<br>none: Does not listen on any address. The same applies if the listen address is omitted.<br><br>Specify addresses numerically (hostnames cannot be used, except for localhost).<br>Malformed listen addresses and addresses on which listening fails are ignored and recorded in the error log. The saved settings are not restored in these cases either.<br>Note that specifying an address other than a loopback address allows SSTP requests from other PCs.<br><br>Example: `ssp.exe --option readonly --sstp-listen 9900,[::1]:9901` |
| --guifont font name \[2.8.75 onward\] | Specifies the font used in the GUI. Not everything is replaced; parts of menus and title bars, for example, currently remain unchanged. |
| --time-shift value \[2.9.39 onward\] | Specifies the offset for "Virtual change of current time" (time machine) at startup. Intended for testing ghosts that depend on the date or time.<br>Specify it using `=` as in `--time-shift=+3600` (a value beginning with `-` cannot be distinguished from an option name when separated by a space).<br>This applies only to the current session and is not saved in the settings. It takes priority over any offset saved in the settings.<br><br>The value is one of the following.<br>+seconds or -seconds: The offset itself, in seconds. The sign is required. Examples: +86400 (1 day ahead), -3600 (1 hour behind)<br>0: Sets the offset to 0 (uses the actual time).<br>Date and time in ISO8601 format: Calculates the offset from the actual time to reach the specified date and time. If no zone is specified, local time is assumed. The clock does not stop; it continues advancing from that date and time. Example: 2026-12-31T23:59:50<br><br>The offset can be up to approximately 200 years in either direction, and fractions of a second are discarded. Values that cannot be interpreted are ignored (the offset remains 0) and recorded in the error log.<br>When SSP is started with this option, the warning about an offset remaining in the settings (a balloon for developers) is not displayed.<br><br>Example: `ssp.exe --option readonly --time-shift=2026-12-31T23:59:50` |
| --allow-timemachine-control \[2.9.39 onward\] | Allows changes to "Virtual change of current time" while SSP is running via Sakura Script `\![timemachine,set,値]` / `\![timemachine,reset]` and SSTP EXECUTE `SetTimeShift`. Intended for testing.<br>When SSP is started without this option, these commands do nothing and a warning is recorded in the error log (to prevent ghost scripts or external programs from changing the global clock).<br>The offset value format is the same as for --time-shift. |

### Offline surface dump

| Switch | Function |
|---|---|
| --offline-dump folder path | Starts in offline dump mode. Loads surfaces.txt from the specified ghost folder, dumps the surface images without actually starting the ghost, and exits immediately. SHIORI/MAKOTO/PIRO are not loaded. No window or message loop is created.<br>Specify the ghost folder path as the argument (the trailing \\ is optional).<br>In 2.8.98 and later, relative paths specified for offline dump options (this option, --dump-output-dir, and --dump-error-log) are resolved relative to the current directory when SSP was started.<br><br>Example: `ssp.exe --offline-dump "C:\SSP\ghost\myGhost" --dump-surface-list "0,1" --dump-output-dir "C:\dump"` |
| --dump-shell folder name or name \[optional\] | Use with --offline-dump. Specify the shell to dump by folder name (a relative path under shell) or name. If omitted, the default shell specified in descript.txt (usually master) is used.<br>In 2.8.98 and later, if the specified shell is not found, an Error is recorded in the error log and nothing is output; the default shell is not used instead. |
| --dump-scope (scope ID) \[optional\] | Use with --offline-dump. Specify the scope ID for the dumped images. Defaults to 0 if omitted. |
| --dump-surface-list list \[optional\] | Use with --offline-dump. Specify the surfaces to dump as a comma-separated list. The surface number prefix (surface) is optional. The [extended format for specifying surface IDs in surfaces.txt](https://ssp.shillest.net/ukadoc/manual/descript_shell_surfaces.html#caption_surfacebraceID) is also supported.<br>Example: `--dump-surface-list "0,1,10"`<br>If this option is omitted, no surfaces are dumped (you can combine this with --dump-error-log to output only parse errors).<br>In 2.8.98 and later, the prefix can be omitted from each element, not just the first (such as `"0,surface1"`). Also, if a surface specified by an individual number rather than a range does not exist, a Warning is recorded in the error log (missing numbers within a range are not logged). |
| --dump-output-dir directory \[optional\] | Use with --offline-dump. Specify the output directory for dumped images. If omitted, the current directory is used (in 2.8.97 and earlier, no dump was performed if omitted). |
| --dump-output-prefix prefix \[optional\] | Use with --offline-dump. Specify the part of the output filename that precedes the surface number. This string replaces the default "surface"; it is not added to it. Defaults to "surface" if omitted.<br>Example: with `--dump-output-prefix "x_"`, surface 0 becomes `x_0.png` (not `x_surface0.png`). |
| --dump-error-log file path \[optional\] | Use with --offline-dump. Writes the error log from loading the shell (such as surfaces.txt parse errors) to the specified path.<br>By specifying only this option and omitting --dump-surface-list, you can check for errors without performing a dump.<br>Example: `ssp.exe --offline-dump "C:\SSP\ghost\myGhost" --dump-error-log "C:\dump\error.csv"`<br><br>Output format: CSV in UTF-8 with a BOM (CRLF line endings). Each line contains one entry, each column is enclosed in ", and " within a column is escaped as "".<br>`"時刻","ゴースト名","レベル","内容"`<br>Time: HH:MM:SS format.<br>Level: One of Info / Notice / Warning / Error / Critical / System.<br>Content: The log message. In 2.8.94 and later, SERIKO-related logs include the source file (relative to the ghost folder) and line number, as in `[SERIKO] shell\master\surfaces.txt:Line=12:Surface=10 ...`. Logs for duplicate definitions also include the location of the earlier definition as `(ファイル名:Line=n)`.<br>In 2.8.94 and later, when this option is specified, up to 10000 log entries are retained and similar entries are not grouped into summary lines (level System), so no logs are missed.<br>If there are no log entries, no file is created (an existing file at the same path is not overwritten or deleted).<br><br>Exit codes: In 2.8.94 and later, the process exits with a code corresponding to the most severe level among the recorded logs.<br>0: No logs, or Info/Notice only<br>1: Warning present (no Error/Critical)<br>2: Error present (no Critical)<br>3: Critical present<br>If loading the ghost itself fails (for example, if descript.txt in the specified folder cannot be read), no log is output and the exit code is 0. |
| --dump-surface-option option \[optional\] \[2.8.57 and later\] | Specifies options for the offline dump feature. The following values are available.<br>backlog: Crops the same area (around the face) as the backlog feature. However, the composite image is output as is, without scaling.<br>collision: Draws the shapes and names of collision regions on the output. This is the same as the collision display in the developer palette, except that names are always shown and bounding rectangles such as the surface outline, active area, and overlap detection area are not drawn.\[2.8.98 and later\]<br>In 2.8.98 and later, multiple values can be specified, separated by commas (example: `--dump-surface-option backlog,collision`).<br>If collision is not specified with this option, collision regions are not drawn regardless of the user setting (the collision display in the developer palette). |
| --dump-bind Dressup specification \[optional\] \[2.9.05 and later\] | Use with --offline-dump. Specify the Dressup state for the dump.<br>You can specify multiple entries in the form "category name,part name,ON/OFF", separated by semicolons. The meaning is the same as [`\![bind]`](https://ssp.shillest.net/ukadoc/manual/list_sakura_script.html#_!_bind,カテゴリ名,パーツ名,数値_): turning a part ON in an exclusive category turns the other parts in that category OFF.<br>If the part name is blank or `__ALL__`, all parts in the category are targeted.<br>For ON/OFF, 1 or true means ON, and 0 or false means OFF. If omitted, it is treated as ON (unlike `\![bind]`, which toggles the state when omitted, this option does not toggle it).<br>Example: `--dump-bind "頭,帽子;服,制服;アクセサリ,__ALL__,0"`<br><br>The starting state is the default for each part specified in the shell's descript.txt (`sakura.bindgroup*.default`); the user's last Dressup state (saved values in `shell\profile`) is not used. Only the specified parts are changed from that starting state.<br>Dressup is applied to the scope specified by --dump-scope.<br>If a nonexistent category or part is specified, a Warning is logged (the exit code for --dump-error-log is 1), only that entry is ignored, and the dump continues.<br>Whitespace before and after category and part names is not removed, so do not put spaces after commas. |
| --dump-animation animation ID \[optional\] \[2.9.05 and later\] | Use with --offline-dump. Plays the specified animation in the same way as `\i[ID]` and outputs numbered images for each frame. Only one ID can be specified (in addition to a number, you can use the name assigned to an animation in surfaces.txt, as with `\i[ID]`).<br>For each surface, the same image as a normal dump (the state after one cycle of runonce animations) is first output as `surface0.png`. Then, each time the specified animation advances to the next pattern, an image is output as `surface0_0000.png`, `surface0_0001.png`, and so on, using a 4-digit sequence starting at 0. The --dump-output-prefix and --dump-surface-option settings also apply to numbered images.<br>Example: `ssp.exe --offline-dump "C:\SSP\ghost\myGhost" --dump-surface-list "0" --dump-animation 10 --dump-output-dir "C:\dump"`<br><br>Animations such as runonce and always run as they do in a normal dump, with the specified animation overlaid on them. Only patterns belonging to the specified animation are included in the numbered sequence; advancing an always animation does not increase the number of images.<br>The dump ends when the specified animation reaches its last pattern (or completes one cycle for always). It also ends if the animation is stopped by another animation's stop or exclusivity.<br>Other animations started by start, alternativestart, or parallelstart are not included in the numbered sequence. If the specified animation contains any of these patterns, a Warning is logged (output continues).<br>Start and stop patterns do not change the image, so they are not counted as frames in the numbered sequence.<br>If the specified ID does not exist on the surface, or cannot be played because it is disabled by Dressup, blocked by exclusivity, or for another reason, a Warning is logged and only the single normal image is output for that surface.<br>The numbered sequence is limited to 10000 images (up to `_9999`); if this limit is reached, a Warning is logged and the sequence is stopped. |

### Offline tools

| Switch | Function |
|---|---|
| --offline-tool type \[2.9.01 and later\] | Starts in offline tool mode. Creates a NAR, update definition file, or archive from the folder specified by --target-dir and exits immediately, without starting a ghost. No ghost events are triggered, and no window or message loop is created.<br>This performs the same operations as the Sakura Script commands `\![execute,createnar]` / `\![execute,createupdatedata]` / `\![execute,compressarchive]`, but the output destination can be specified freely without restrictions (such as being limited to folders managed by SSP).<br>Specify one of the following types (case-insensitive):<br><br>nar: Creates a NAR file. Exclusions specified by nonar in `developer_options.txt`, .narignore, and so on are applied as in normal NAR creation. If there is no install.txt directly in the folder, the type and name are determined from descript.txt (or `ghost\master\descript.txt`), and install.txt is created in the target folder and included in the NAR. If the type and name cannot be determined, the operation fails.<br>updatedata: Creates an update definition file. If the --output filename ends in .dau, it uses the same format as updates2.dau; otherwise, it uses the updates.txt format. Only the specified file is created. Neither updates2.dau nor updates.txt is created or deleted directly in the target folder or in `ghost\master`. Exclusions specified by noupdate in `developer_options.txt`, .updateignore, and so on are applied as usual.<br>archive: Compresses the target folder as is. Exclusion settings such as .narignore are not read (hidden files and folders are not included). The format is determined by the --output extension: .7z produces 7z format; all others produce zip format.<br><br>For all types, an existing output file is overwritten. If the output destination is inside the target folder, the output file itself is not included. The output folder must already exist.<br>If relative paths are specified for --target-dir or --output, they are resolved relative to the current directory when SSP was started.<br><br>Exit codes:<br>0: Success<br>1: Invalid arguments (unknown type, --target-dir or --output omitted, or --target-dir does not exist or is not a folder)<br>2: Creation failed (the output destination is not writable, the NAR type and name could not be determined, updatedata encountered an unreadable file or a folder hierarchy that was too deep (more than 32 levels), etc.). A partially created file may remain even if the operation fails.<br><br>Example: `ssp.exe --offline-tool nar --target-dir "C:\src\myGhost" --output "C:\out\myGhost.nar"`<br>Example: `ssp.exe --offline-tool updatedata --target-dir "C:\src\myGhost" --output "C:\out\updates2.dau"`<br>Example: `ssp.exe --offline-tool archive --target-dir "C:\src\data" --output "C:\out\data.7z" --password "pass"` |
| --target-dir folder-path \[2.9.01 and later\] | Used with --offline-tool (required). Specifies the folder to process (a trailing \\ is optional). For NARs and update definition files, specify the root folder of the ghost or other item (the folder containing descript.txt, install.txt, and the ghost folder). |
| --output file-path \[2.9.01 and later\] | Used with --offline-tool (required). Specifies the path of the file to create. |
| --password password \[optional\] \[2.9.01 and later\] | Used with --offline-tool nar or archive. Creates an AES-encrypted ZIP with the specified password (7z encryption is used for 7z format). Ignored for updatedata.<br>The password remains visible on the command line, so handle it with care. |

### Other

| Switch | Function |
|---|---|
| `initial_install.nar` | Although this is not a startup option, placing a NAR file named <strong>`initial_install.nar`</strong> in the same folder as ssp.exe causes it to be installed silently (without a confirmation dialog) and overwrite existing files when SSP starts. After installation, `initial_install.nar` is automatically deleted. This can be used, for example, when distributing SSP bundled with ghosts. \[2.7.52 and later\] |
