# Startup options

You can launch ssp.exe with the following options (switches).

## What are startup options?

Startup options let you change settings when launching Windows software.<br>
For more information, look up terms such as runtime options, command-line options, and startup options.

## How to use them

There are several ways to use startup options.<br>
For example, you can use them from the Command Prompt or the Run dialog.<br>
Here is how to create a shortcut with startup options.

1. Create a shortcut to ssp.exe.<br>
   Example: Right-click ssp.exe→Create shortcut
2. Open the properties of the shortcut you created.<br>
   Example: Right-click the shortcut→Properties
3. In the properties, find the path to ssp.exe in the Target field and enclose the entire path in double quotation marks ("").
4. Add a single space after the enclosed path, followed by the startup options listed below.<br>
   Example: "C:/User/Document/.../SSP/ssp.exe" --random
5. Click OK to close the properties, and give the shortcut a descriptive name.<br>
   Example: SSP-Random startup
6. Run the shortcut to launch SSP with the specified options, rather than launching ssp.exe normally.

## List of options

The `--オプション名` format is recommended for each option. The short option formats `/x` and `-x` are still supported for backward compatibility.

For options that take a value, separate the option name and value with a space, as in `--オプション名 値`. If the value contains spaces, enclose it in double quotation marks ("").

From version 2.8.97 onward, the `--オプション名=値` format is also accepted (example: `--sstp-listen=9900`). This page primarily uses the space-separated format. The `=` format cannot be used with short options in the `/x` format.

### --option options

Multiple --option options can be specified as a comma-separated list (example: `--option bootunlock,standalone`).

| Switch | Function |
|---|---|
| --option nobootcheck<br>(formerly: /o nobootcheck) | Disable the abnormal termination check |
| --option layered<br>(formerly: /o layered) | Enable translucent windows |
| --option region<br>(formerly: /o region) | Disable translucent windows (region mode) |
| --option bootunlock<br>(formerly: /o bootunlock) | Skip the duplicate launch check |
| --option standalone<br>(formerly: /o standalone) | If SSP.exe is already running, disable the mechanism that delegates operations such as installation and ghost startup to the running SSP.exe instance. Instead, this instance always starts ghosts and performs installations itself.<br>Combine this with the option to skip the duplicate launch check, as in --option bootunlock,standalone, to run multiple instances of SSP.exe without any warnings. |
| --option kiosk<br>(formerly: /o kiosk) | Enable KIOSK mode. Its behavior is as follows. \[2.6.54～\]<br>--option bootunlock,standalone is enabled<br>alignmenttodesktop is always set to free<br>Mouse and keyboard input is not accepted<br>The duplicate launch check is not affected in any way<br>No notification area or taskbar icon is displayed<br>Ghost and shell settings managed by SSP are not saved<br>No startup window is displayed<br>Errors are not reported |
| --option readonly<br>(formerly: /o readonly) | Enable read-only mode. \[2.8.96 onward\]<br>SSP starts without making any persistent changes to the user environment. Use this to try SSP without altering settings, or to run it temporarily on someone else's PC.<br>On-screen behavior and interactions with ghosts work as usual; input and display are not restricted as they are in KIOSK mode. This mode is independent of KIOSK mode, and both can be used together, as in --option kiosk,readonly.<br><br>Its behavior is as follows.<br>--option bootunlock,standalone is enabled (because delegating operations to a running SSP instance could cause that instance to write settings)<br>The duplicate launch check is not affected in any way<br>Preferences and ghost, shell, balloon, and plugin settings are not saved<br>Startup history, usage statistics, caches, cookies, vanish records, SSTP settings, POP settings, and Ukagaka messenger information and logs are not saved<br>Calendar schedules (schedule.ics) are not saved<br>Save data is not shared (neither uploaded to the cloud nor restored from the cloud to the local system)<br>Nothing is written to the registry. File associations, shortcuts, and Jump List entries are not created, and items are not added to Recent Items<br>The desktop wallpaper and background color are not changed<br>The Recycle Bin is not emptied<br>Ghost folders are not deleted when a ghost vanishes<br>SSP, ghosts, balloons, plugins, and language resources are not updated automatically. Manual network updates and NAR installations are also disabled<br>`initial_install.nar` is not installed<br>NTP time sync via SNTP is not performed<br><br>You can change settings as usual, but they are not written back to files when SSP exits, so they do not carry over to the next launch.<br>Temporary files needed for operation (in the temporary folder) are still created as usual and discarded when SSP exits. |
| --option dontloadmodule<br>(formerly: /o dontloadmodule) | Do not load SHIORI/MAKOTO/PLUGIN/HEADLINE/CALENDAR components |
| --option dpiaware<br>(formerly: /o dpiaware) | Start with DPI Awareness Mode set to Per-Monitor V2 |
| --option callghost<br>(formerly: /o callghost) | When used with --install, automatically call the ghost after installation is complete. |
| --option deletesource<br>(formerly: /o deletesource) | When used with --install, delete the NAR after it is successfully installed. |

| Switch | Function |
|---|---|
| --fmo-name FMO name<br>(formerly: /f FMO name) | Forces the FMO name used for writing to the specified name. |
| --random<br>(formerly: /r) | Starts a random ghost regardless of the settings. |
| --ghost folder name/ghost name<br>(formerly: /g folder name/ghost name) | Starts the specified ghost. Specify multiple ghosts separated by spaces to start them all. As of 2.9.35, you can also specify a ghost's UUID (the `uuid` in the property system, in a form such as `R5dVNluBvKjtQqjP0dAuoA==`) instead of its folder name/ghost name. | --ssf SSF file name<br>(formerly: /s SSF file name) | Runs an [SSF file](https://emily.shillest.net/specwiki/?SSP/%E4%BB%95%E6%A7%98%E6%9B%B8/SSF%E3%83%95%E3%82%A1%E3%82%A4%E3%83%AB). If specified when SSP starts, it waits until the first ghost has started before executing. |
| --windowmode mode \[optional\] | As of 2.8.78, starts in the experimental "[Window mode](windowmode.md)". Ghosts run in a window treated as a virtual screen, making capture operations easier and preventing them from affecting the entire desktop.<br>As of 2.8.86, you can specify a mode. The available modes are listed below. If omitted, the previous setting is used (the initial value is shared).<br>shared: Places all running ghosts in a single window.<br>perghost: Opens one window per ghost.<br>As of 2.8.86, the Window mode state is saved as a setting, so SSP starts in the previous state even without this option. The SSTP server list in Preferences is view-only, and entries cannot be added, removed, enabled, or disabled.<br>This is intended for use with --option readonly to run a test instance of SSP that does not interfere with other running instances.<br><br>Multiple listen addresses can be specified, separated by commas. The formats are as follows.<br>Port number: Listens on the IPv4 and IPv6 loopback addresses (127.0.0.1 and ::1). Example: 9801<br>localhost:port number: Same as specifying only a port number.<br>IPv4 address:port number: Listens only on the specified address. Specify 0.0.0.0 to listen on all IPv4 interfaces. Example: \[::1\]:9801<br>none: Does not listen on any address. The same applies if the listen address is omitted.<br><br>Specify addresses numerically (hostnames cannot be used, except for localhost).<br>Malformed listen addresses and addresses on which listening fails are ignored and recorded in the error log. | --guifont font name \[2.8.75 and later\] | Specifies the font used for the GUI. Not everything is replaced; some menu items and title bars, for example, currently remain unchanged. |
| --time-shift value \[2.9.39 and later\] | Specifies the offset for "Virtual change of current time" (time machine) at startup. Intended for testing ghosts that depend on the date or time.<br>Specify it using the `=` form, as in `--time-shift=+3600` (a value starting with `-` cannot be distinguished from an option name when separated by a space).<br>This applies only to the current session and is not saved in the settings. It takes precedence over any offset saved in the settings.<br><br>The value must be one of the following.<br>+seconds or -seconds: The offset itself, in seconds. The sign is required. Examples: +86400 (1 day ahead), -3600 (1 hour ago)<br>0: Sets the offset to 0 (the actual time).<br>Date and time in ISO8601 format: Calculates the offset from the actual time to the specified date and time. ### Offline surface dump

| Switch | Function |
|---|---|
| --offline-dump folder path | Starts in offline dump mode. Loads surfaces.txt from the specified ghost folder, dumps surface images without actually starting the ghost, and exits immediately. SHIORI/MAKOTO/PIRO are not loaded. No window or message loop is created.<br>Specify the ghost folder path as the argument (the trailing \\ is optional).<br>As of 2.8.98, relative paths specified for offline dump options (this option, --dump-output-dir, and --dump-error-log) are resolved relative to the current directory when SSP was started.<br><br>Example: `ssp.exe --offline-dump "C:\SSP\ghost\myGhost" --dump-surface-list "0,1" --dump-output-dir "C:\dump"` |
| --dump-shell folder name or name \[optional\] | Use with --offline-dump. Specifies the shell to dump by folder name (a path relative to shell) or name. If omitted, the default shell specified in descript.txt (usually master) is used.<br>As of 2.8.98, if the specified shell is not found, an Error is recorded in the error log and nothing is output, rather than dumping the default shell. |
| --dump-scope (scope ID) \[optional\] | Use with --offline-dump. Specifies the scope ID for the dumped images. Defaults to 0. |
| --dump-surface-list list \[optional\] | Use with --offline-dump. Specifies the surfaces to dump as a comma-separated list. The surface number prefix (surface) is optional. The [extended surface ID syntax for surfaces.txt](https://ssp.shillest.net/ukadoc/manual/descript_shell_surfaces.html#caption_surfacebraceID) can also be used.<br>Example: `--dump-surface-list "0,1,10"`<br>If this option is omitted, no surfaces are dumped (it can be combined with --dump-error-log to output only parse errors).<br>As of 2.8.98, the prefix can be omitted from each element, not just the first (for example, `"0,surface1"`). Also, if a surface specified by an individual number rather than a range does not exist, a Warning is recorded in the error log (missing numbers within a range are not logged). |
| --dump-output-dir directory \[optional\] | Use with --offline-dump. Specifies the output directory for dumped images. If omitted, the current directory is used (in 2.8.97 and earlier, no dump was performed if omitted). |
| --dump-output-prefix prefix \[optional\] | Use with --offline-dump. Specifies the part of the output filename preceding the surface number. This string replaces the default "surface" rather than being added to it. Defaults to "surface".<br>Example: With `--dump-output-prefix "x_"`, surface 0 becomes `x_0.png` (not `x_surface0.png`). |
| --dump-error-log file path \[optional\] | Use with --offline-dump. Writes the error log from loading the shell (such as surfaces.txt parse errors) to the specified path.<br>By specifying this option without --dump-surface-list, you can check for errors without performing a dump.<br>Example: `ssp.exe --offline-dump "C:\SSP\ghost\myGhost" --dump-error-log "C:\dump\error.csv"`<br><br>Output format: UTF-8 CSV with a BOM (CRLF line endings). Each line is one entry; each column is enclosed in ", and any " within a column is escaped as "".<br>`"時刻","ゴースト名","レベル","内容"`<br>Time: HH:MM:SS format.<br>Level: One of Info / Notice / Warning / Error / Critical / System.<br>Content: The body of the log entry. As of 2.8.94, SERIKO-related log entries include the source file (relative to the ghost folder) and line number, as in `[SERIKO] shell\master\surfaces.txt:Line=12:Surface=10 ...`. Duplicate definition entries also include the location of the earlier definition as `(ファイル名:Line=n)`.<br>As of 2.8.94, when this option is specified, up to 10000 log entries are retained, and similar entries are not grouped into summary lines (level System), preventing entries from being missed.<br>If there are no log entries, no file is created (an existing file at the same path is neither overwritten nor deleted).<br><br>Exit code: As of 2.8.94, the process exits with a code corresponding to the highest severity level recorded in the log.<br>0: No log entries, or only Info/Notice<br>1: Warning present (no Error/Critical)<br>2: Error present (no Critical)<br>3: Critical present<br>If loading the ghost itself fails (for example, if descript.txt in the specified folder cannot be read), no log is output and the exit code is 0. |
| --dump-surface-option option \[optional\] \[2.8.57 and later\] | Specifies options for the offline dump feature. The following options are available.<br>backlog: Crops the same area as the backlog feature (around the face). However, the composite image is output as-is without scaling.<br>collision: Draws collision shapes and names on the output. This is the same as the collision display in the developer palette, except that names are always shown and bounding rectangles such as the surface outline, valid area, and overlap detection area are not drawn. \[2.8.98 and later\]<br>As of 2.8.98, multiple options can be specified, separated by commas (example: `--dump-surface-option backlog,collision`).<br>If collision is not specified with this option, collisions are not drawn regardless of the user setting (the collision display in the developer palette). |
| --dump-bind Dressup specification \[optional\] \[2.9.05 and later\] | Use with --offline-dump. Specifies the Dressup state for the dump.<br>Multiple specifications in the form "category name,part name,ON/OFF" can be separated by semicolons. The meaning is the same as for [`\![bind]`](https://ssp.shillest.net/ukadoc/manual/list_sakura_script.html#_!_bind,カテゴリ名,パーツ名,数値_): turning a part ON in an exclusive category turns the other parts in that category OFF.<br>If the part name is empty or `__ALL__`, all parts in the category are affected.<br>For ON/OFF, 1 or true means ON, and 0 or false means OFF. If omitted, it is treated as ON (unlike `\![bind]`, which toggles the state when omitted).<br>Example: `--dump-bind "頭,帽子;服,制服;アクセサリ,__ALL__,0"`<br><br>The starting state is the default for each part specified in the shell's descript.txt (`sakura.bindgroup*.default`); the user's last Dressup state (saved values in `shell\profile`) is not used. Only the specified parts are changed from that state.<br>Dressup is applied to the scope specified by --dump-scope.<br>If a nonexistent category or part is specified, a Warning is logged (the exit code for --dump-error-log is 1), and the dump continues, ignoring only that specification.<br>Whitespace before and after category and part names is not removed, so do not insert spaces after commas. |
| --dump-animation animation ID \[optional\] \[2.9.05 and later\] | Use with --offline-dump. Plays the specified animation like `\i[ID]` and outputs sequentially numbered images for each frame. Only one ID can be specified (in addition to a number, an animation name assigned in surfaces.txt can be used, as with `\i[ID]`).<br>For each surface, the same image as a normal dump (the state after runonce animations have completed one cycle) is first output as `surface0.png`. Then, each time the specified animation advances to the next pattern, an image is output as `surface0_0000.png`, `surface0_0001.png`, and so on, using four-digit sequential numbers starting at 0. The --dump-output-prefix and --dump-surface-option settings also apply to the numbered images.<br>Example: `ssp.exe --offline-dump "C:\SSP\ghost\myGhost" --dump-surface-list "0" --dump-animation 10 --dump-output-dir "C:\dump"`<br><br>Animations such as runonce and always run as they do in a normal dump, with the specified animation layered on top. Only the patterns of the specified animation are numbered; the number of images does not increase when an always animation advances.<br>The dump ends when the specified animation reaches its last pattern (or completes one cycle for always). It also ends if the animation is stopped by another animation's stop or exclusivity.<br>Other animations launched by start, alternativestart, or parallelstart are not included in the numbered sequence. If the specified animation contains these patterns, a Warning is logged (output continues).<br>Patterns such as start and stop do not change the image, so they are not counted as frames in the sequence.<br>If the specified ID does not exist on that surface, or cannot be played because it is disabled by Dressup, blocked by exclusivity, or for another reason, a Warning is logged and only the usual single image is output for that surface.<br>The sequence is limited to 10000 images (up to `_9999`); if this limit is reached, a Warning is logged and output stops. |

### Offline tools

| Switch | Function |
|---|---|
| --offline-tool type \[2.9.01 onward\] | Starts in offline tool mode. Without starting a ghost, creates a NAR, update definition file, or archive from the folder specified by --target-dir, then exits immediately. No ghost events are triggered, and no window or message loop is created.<br>This is equivalent to the Sakura Script commands `\![execute,createnar]` / `\![execute,createupdatedata]` / `\![execute,compressarchive]`, but the output location can be specified freely, without restrictions such as requiring it to be in a folder managed by SSP.<br>Specify one of the following types (case-insensitive).<br><br>nar: Creates a NAR file. Exclusions specified by nonar in `developer_options.txt`, .narignore, and similar settings apply as with normal NAR creation. If install.txt is not directly inside the folder, the type and name are determined from descript.txt (or `ghost\master\descript.txt`), and install.txt is created in the target folder before being included. The operation fails if the type and name cannot be determined.<br>updatedata: Creates an update definition file. If the --output filename ends in .dau, it uses the same format as updates2.dau; otherwise, it uses the updates.txt format. Only the specified file is created. No updates2.dau or updates.txt files are created or deleted directly inside the target folder or in `ghost\master`. Exclusions specified by noupdate in `developer_options.txt`, .updateignore, and similar settings apply as usual.<br>archive: Compresses the target folder as is. Exclusion settings such as .narignore are not read (hidden files and folders are not included). The format is determined by the --output extension: .7z produces a 7z file, and any other extension produces a zip file.<br><br>For all types, an existing output file is overwritten. If the output location is inside the target folder, the output file itself is not included. The output folder must already exist.<br>If relative paths are specified for --target-dir or --output, they are resolved relative to the current directory when SSP was started.<br><br>Exit codes:<br>0: Success<br>1: Invalid arguments (unknown type, missing --target-dir or --output, or --target-dir does not exist or is not a folder)<br>2: Creation failed (for example, the output location is not writable, the NAR type and name cannot be determined, or updatedata encountered an unreadable file or a folder hierarchy that is too deep (more than 32 levels)). A partially created file may remain even if the operation fails.<br><br>Example: `ssp.exe --offline-tool nar --target-dir "C:\src\myGhost" --output "C:\out\myGhost.nar"`<br>Example: `ssp.exe --offline-tool updatedata --target-dir "C:\src\myGhost" --output "C:\out\updates2.dau"`<br>Example: `ssp.exe --offline-tool archive --target-dir "C:\src\data" --output "C:\out\data.7z" --password "pass"` |
| --target-dir folder-path \[2.9.01 onward\] | Used with --offline-tool (required). Specifies the folder to process (the trailing \\ is optional). For NARs and update definition files, specify the root folder of the ghost or other item (the folder containing descript.txt, install.txt, and the ghost folder). |
| --output file-path \[2.9.01 onward\] | Used with --offline-tool (required). Specifies the path of the file to create. |
| --password password \[optional\] \[2.9.01 onward\] | Used with the nar or archive type of --offline-tool. Creates an AES-encrypted ZIP using the specified password (7z encryption is used for the 7z format). Ignored for updatedata.<br>Handle the password with care, as it remains in plain text on the command line. |

### Other

| Switch | Function |
|---|---|
| `initial_install.nar` | This is not a startup option, but if a NAR file named <strong>`initial_install.nar`</strong> is placed in the same folder as ssp.exe, it is installed silently (without a confirmation dialog), overwriting any existing installation, when SSP starts. After installation, `initial_install.nar` is automatically deleted. This can be used when distributing SSP bundled with ghosts or other items. \[2.7.52 onward\] |
