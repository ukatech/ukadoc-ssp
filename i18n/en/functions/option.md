# Startup options

You can launch ssp.exe with the following options (switches).

## What are startup options?

Startup options let you change settings when launching Windows software.<br>
For more information, look up terms such as runtime options, command-line options, or startup options.

## How to use them

There are several ways to use startup options.<br>
For example, you can use them from the Command Prompt or the Run dialog.<br>
Here is how to create a shortcut for a specific option.

1. Create a shortcut to ssp.exe.<br>
   Example: Right-click ssp.exe→Create shortcut
2. Open the properties of the shortcut you created.<br>
   Example: Right-click the shortcut→Properties
3. Check that the path to ssp.exe is in the "Target" field of the properties, then enclose the entire path in double quotation marks.
4. Add a space after the enclosed path, then enter one of the startup options listed below.<br>
   Example: "C:/User/Document/.../SSP/ssp.exe" --random
5. Click OK to close the properties, and give the shortcut a descriptive name.<br>
   Example: SSP-Random startup
6. When you run the shortcut, SSP starts with the option applied, unlike when you launch ssp.exe normally.

## List of options

The `--オプション名` format is recommended for each option. The short option formats `/x` and `-x` are still supported for backward compatibility.

For options that take a value, separate the option name and value with a space, as in `--オプション名 値`. If the value contains spaces, enclose it in double quotation marks.

Starting with 2.8.97, the `--オプション名=値` format is also accepted as an alternative (example: `--sstp-listen=9900`). This page primarily uses the space-separated format. The `=` format cannot be used with short options in the `/x` format.

### --option options

You can specify multiple --option options separated by commas (example: `--option bootunlock,standalone`).

| Switch | Function |
|---|---|
| --option nobootcheck<br>(old: /o nobootcheck) | Disable the abnormal termination check |
| --option layered<br>(old: /o layered) | Enable translucent windows |
| --option region<br>(old: /o region) | Disable translucent windows (region mode) |
| --option bootunlock<br>(old: /o bootunlock) | Skip the multiple-instance check |
| --option standalone<br>(old: /o standalone) | When SSP.exe is already running, disable the mechanism that delegates operations such as installation and ghost startup to the running instance, and always start ghosts or perform installations in this instance.<br>Combine this with the option to skip the multiple-instance check, as in --option bootunlock,standalone, to launch multiple instances of SSP.exe without any warnings. |
| --option kiosk<br>(old: /o kiosk) | Enable KIOSK mode. Its behavior is as follows. \[2.6.54 and later\]<br>--option bootunlock,standalone is enabled<br>alignmenttodesktop is always set to free<br>Mouse and keyboard input is ignored<br>The multiple-instance check is not affected in any way<br>Notification area and taskbar icons are not displayed<br>Ghost and shell settings managed by SSP are not saved<br>The startup window is not displayed<br>Errors are not reported |
| --option readonly<br>(old: /o readonly) | Enable read-only mode. \[2.8.96 and later\]<br>Start without making any persistent changes to the user environment. Use this to test behavior without affecting settings, or to temporarily run SSP on someone else's PC.<br>On-screen behavior and interactions with ghosts work as usual; input is not blocked and display is not restricted as in KIOSK mode. This mode is independent of KIOSK mode, and they can be used together, as in --option kiosk,readonly.<br><br>Its behavior is as follows.<br>--option bootunlock,standalone is enabled (because delegating operations to a running SSP instance would cause that instance to write settings)<br>The multiple-instance check is not affected in any way<br>Preferences and ghost, shell, balloon, and plugin settings are not saved<br>Startup history, usage statistics, cache, cookies, vanish records, SSTP settings, POP settings, and Ukagaka messenger information and logs are not saved<br>Calendar schedules (schedule.ics) are not saved<br>Save data is not shared (neither exported to the cloud nor restored from the cloud to the local system)<br>Nothing is written to the registry. File associations and shortcuts are not created, jump lists are not registered, and items are not added to "Recent items"<br>The desktop wallpaper and background color are not changed<br>The Recycle Bin is not emptied<br>Ghost folders are not deleted even when a ghost vanishes<br>SSP, ghosts, balloons, plugins, and language resources are not updated automatically. Manual network updates and NAR installations are also disabled<br>`initial_install.nar` is not installed<br>NTP time sync via SNTP is not performed<br><br>You can change settings as usual, but they are not written back to files on exit and will not carry over to the next launch.<br>Temporary files needed for operation (in the temporary folder) are still created and are discarded on exit. |
| --option dontloadmodule<br>(old: /o dontloadmodule) | Do not load SHIORI/MAKOTO/PLUGIN/HEADLINE/CALENDAR components |
| --option dpiaware<br>(old: /o dpiaware) | Start with DPI Awareness Mode set to Per-Monitor V2 |
| --option callghost<br>(old: /o callghost) | When used with --install, automatically call the ghost after installation is complete. |
| --option deletesource<br>(old: /o deletesource) | When used with --install, delete the NAR after it is successfully installed. |

### General options

| Switch | Function |
|---|---|
| --fmo-name FMO name<br>(formerly: /f FMO name) | Forces the name of the FMO to write to the specified name. |
| --random<br>(formerly: /r) | Starts a random ghost regardless of the settings. |
| --ghost folder name/ghost name<br>(formerly: /g folder name/ghost name) | Starts the specified ghosts. Separate multiple ghosts with spaces to start them together. As of 2.9.35, you can also specify a ghost's UUID (the `uuid` in the property system, in a form such as `R5dVNluBvKjtQqjP0dAuoA==`) instead of its folder name/ghost name. If specified when SSP starts, the first specified ghost is started as the first ghost. <br>As of 2.8.99, if you specify an absolute path to a ghost folder when starting SSP (for example, `ssp.exe --ghost "C:\Users\user\Desktop\myGhost"`) and the ghost is not in a load folder, its parent folder (`C:\Users\user\Desktop\` in this example) is temporarily added to the ghost load folders for that session. This applies only to folders containing `ghost\master\descript.txt`.<br>Temporarily added folders are not saved in the settings. They appear as "(temporary)" on the folder settings screen and cannot be edited or deleted. They are also not offered as installation destinations for ghosts. If you explicitly add the same folder from the folder settings screen, it is saved as a regular load folder.<br>This process does not occur if SSP is already running and the arguments are passed to the running instance. |
| --help<br>(formerly: /?) | Opens the startup options help page in a browser. |
| --help file name<br>(formerly: /? file name) | Opens the help page for the specified file name in a browser. |
| --ukagaka-link x-ukagaka-link:URL<br>(formerly: /m x-ukagaka-link:URL) | Performs the same action as opening x-ukagaka-link:URL. If specified when SSP starts, it waits for the first ghost to start before executing. |
| --install NAR file name<br>(formerly: /i NAR file name) | Installs a NAR. If SSP is already running, it passes the installation to the running instance; otherwise, it installs the NAR itself and then continues startup.<br>Specify multiple NARs separated by spaces to install them in order.<br>This also works if the receiving SSP is displaying a warning dialog stating that no ghosts are installed (the "Please do something" dialog).<br>In that case, if --option callghost is also specified, the button to continue startup in the warning dialog is automatically pressed and startup continues. |
| --ssf SSF file name<br>(formerly: /s SSF file name) | Runs an [SSF file](https://emily.shillest.net/specwiki/?SSP/%E4%BB%95%E6%A7%98%E6%9B%B8/SSF%E3%83%95%E3%82%A1%E3%82%A4%E3%83%AB). If specified when SSP starts, it waits for the first ghost to start before executing. |
| --windowmode mode \[optional\] | As of 2.8.78, starts in the experimental "[Window mode](windowmode.md)". This starts ghosts within a window treated as a single virtual screen, making capture operations easier and preventing effects on the entire desktop.<br>As of 2.8.86, you can specify a mode from the options below. If omitted, the previous setting is used (initially shared).<br>shared: Groups all running ghosts in one window.<br>perghost: Creates a separate window for each ghost.<br>As of 2.8.86, the Window mode state is saved as a setting, so SSP starts in the previous state even without this option. To turn it off, use "Settings" in the right-click menu or "Streaming" in Preferences. |
| --sstp-listen listen address | Starts SSP with a temporarily specified SSTP server listen address. \[2.8.97 and later\]<br>The saved SSTP server listen settings are not loaded; the server listens only on the specified addresses.<br>The listen settings for this session are not saved. The SSTP server list in Preferences is read-only, so you cannot add, delete, enable, or disable entries.<br>This option is intended for use with --option readonly to run a test instance of SSP without interfering with other running instances.<br><br>You can specify multiple listen addresses separated by commas. The formats are as follows.<br>Port number: Listens on the IPv4 and IPv6 loopback addresses (127.0.0.1 and ::1). Example: 9801<br>localhost:port number: Same as specifying only a port number.<br>IPv4 address:port number: Listens only on the specified address. Specify 0.0.0.0 to listen on all IPv4 interfaces. Example: 192.168.0.5:9801<br>\[IPv6 address\]:port number: Enclose the IPv6 address in \[\]. Specify \[::\] to listen on all IPv6 interfaces. Example: \[::1\]:9801<br>none: Does not listen on any address. The same applies if the listen address is omitted.<br><br>Specify addresses numerically (hostnames cannot be used, except for localhost).<br>Malformed listen addresses and addresses that fail to bind are ignored and recorded in the error log. The saved settings are not restored in these cases.<br>Be aware that specifying a non-loopback address allows SSTP requests from other PCs.<br><br>Example: `ssp.exe --option readonly --sstp-listen 9900,[::1]:9901` |
| --guifont font name \[2.8.75 and later\] | Specifies the font used for the GUI. This does not replace every font; some menu items and title bars, for example, are currently unaffected. |

### Offline surface dump

| Switch | Function |
|---|---|
| --offline-dump folder path | Starts in offline dump mode. Loads surfaces.txt from the specified ghost folder, dumps the surface images without actually starting the ghost, and exits immediately. SHIORI/MAKOTO/PIRO are not loaded. No window or message loop is created.<br>Specify the ghost folder path as the argument (the trailing \\ is optional).<br>In 2.8.98 and later, relative paths specified for offline dump options (this option, --dump-output-dir, and --dump-error-log) are resolved relative to the current directory when SSP was started.<br><br>Example: `ssp.exe --offline-dump "C:\SSP\ghost\myGhost" --dump-surface-list "0,1" --dump-output-dir "C:\dump"` |
| --dump-shell folder name or name \[optional\] | Use with --offline-dump. Specifies the shell to dump by folder name (the relative path under shell) or name. If omitted, the default shell specified in descript.txt (usually master) is used.<br>In 2.8.98 and later, if the specified shell is not found, an Error is recorded in the error log and nothing is output; the default shell is not dumped instead. |
| --dump-scope (scope ID) \[optional\] | Use with --offline-dump. Specifies the scope ID for the dumped images. Defaults to 0. |
| --dump-surface-list list \[optional\] | Use with --offline-dump. Specifies the surfaces to dump as a comma-separated list. The surface number prefix (surface) may be omitted. The [extended surface ID specification format for surfaces.txt](https://ssp.shillest.net/ukadoc/manual/descript_shell_surfaces.html#caption_surfacebraceID) can also be used.<br>Example: `--dump-surface-list "0,1,10"`<br>If this option is omitted, no surfaces are dumped (it can be combined with --dump-error-log to output only parse errors).<br>In 2.8.98 and later, the prefix may be omitted from any element, not just the first (for example, `"0,surface1"`). Also, if a surface specified by an individual number rather than a range does not exist, a Warning is recorded in the error log (missing numbers within a range are not logged). |
| --dump-output-dir directory \[optional\] | Use with --offline-dump. Specifies the output directory for dumped images. If omitted, the current directory is used (in 2.8.97 and earlier, no dump was performed if omitted). |
| --dump-output-prefix prefix \[optional\] | Use with --offline-dump. Specifies the part of the output filename before the surface number. The default "surface" is replaced by this string, not added to it. Defaults to "surface".<br>Example: With `--dump-output-prefix "x_"`, surface 0 becomes `x_0.png` (not `x_surface0.png`). |
| --dump-error-log file path \[optional\] | Use with --offline-dump. Writes the error log from loading the shell (such as surfaces.txt parse errors) to the specified path.<br>By specifying this option without --dump-surface-list, you can check for errors without performing a dump.<br>Example: `ssp.exe --offline-dump "C:\SSP\ghost\myGhost" --dump-error-log "C:\dump\error.csv"`<br><br>Output format: UTF-8 CSV with BOM (CRLF line endings). Each line is one entry, each column is enclosed in ", and any " within a column is escaped as "".<br>`"時刻","ゴースト名","レベル","内容"`<br>Time: HH:MM:SS format.<br>Level: Info / Notice / Warning / Error / Critical / System.<br>Content: The body of the log entry. In 2.8.94 and later, SERIKO-related log entries include the source file (relative to the ghost folder) and line number, as in `[SERIKO] shell\master\surfaces.txt:Line=12:Surface=10 ...`. Duplicate definition entries also include the location of the earlier definition as `(ファイル名:Line=n)`.<br>In 2.8.94 and later, when this option is specified, up to 10000 log entries are retained, and similar entries are not grouped into summary lines (level System), so no entries are missed.<br>If there are no log entries, no file is created (an existing file at the same path is neither overwritten nor deleted).<br><br>Exit code: In 2.8.94 and later, the process exits with a code corresponding to the most severe level among the recorded log entries.<br>0: No log entries, or Info/Notice only<br>1: Warning present (no Error/Critical)<br>2: Error present (no Critical)<br>3: Critical present<br>If loading the ghost itself fails (for example, descript.txt in the specified folder cannot be read), no log is output and the exit code is 0. |
| --dump-surface-option option \[optional\] \[2.8.57 and later\] | Specifies options for the offline dump function. The available options are as follows.<br>backlog: Crops the same area as the backlog function (around the face). The composite image is output as-is, without scaling.<br>collision: Draws collision shapes and names on the output. This is the same as the collision display in the developer palette, except that names are always shown and outline rectangles such as the surface boundary, active area, and overlap detection area are not drawn.\[2.8.98 and later\]<br>In 2.8.98 and later, multiple options can be specified, separated by commas (example: `--dump-surface-option backlog,collision`).<br>If collision is not specified with this option, collision information is not drawn, regardless of the user's setting (collision display in the developer palette). |
| --dump-bind Dressup specification \[optional\] \[2.9.05 and later\] | Use with --offline-dump. Specifies the Dressup state for the dump.<br>You can specify multiple entries in the form "category name,part name,ON/OFF", separated by semicolons. The meaning is the same as for [`\![bind]`](https://ssp.shillest.net/ukadoc/manual/list_sakura_script.html#_!_bind,カテゴリ名,パーツ名,数値_): turning a part ON in a category with exclusive settings turns the other parts in that category OFF.<br>If the part name is empty or `__ALL__`, all parts in the category are targeted.<br>For ON/OFF, 1 or true means ON, and 0 or false means OFF. If omitted, it is treated as ON (unlike `\![bind]`, where omission toggles the state, this does not toggle it).<br>Example: `--dump-bind "頭,帽子;服,制服;アクセサリ,__ALL__,0"`<br><br>The starting state is the default for each part specified in the shell's descript.txt (`sakura.bindgroup*.default`); the user's last Dressup state (the saved values in `shell\profile`) is not used. Only the specified parts are changed from that starting state.<br>Dressup is applied to the scope specified by --dump-scope.<br>If a nonexistent category or part is specified, a Warning is logged (the exit code for --dump-error-log is 1), only that specification is ignored, and the dump continues.<br>Whitespace around category and part names is not removed, so do not add spaces after commas. |
| --dump-animation animation ID \[optional\] \[2.9.05 and later\] | Use with --offline-dump. Plays the specified animation as with `\i[ID]` and outputs numbered images for each frame. Only one ID can be specified (in addition to a number, you can use a name assigned to an animation in surfaces.txt, as with `\i[ID]`).<br>For each surface, the same image as a normal dump (the state after runonce animations have completed one cycle) is first output as `surface0.png`. Then, each time the specified animation advances to the next pattern, an image is output as `surface0_0000.png`, `surface0_0001.png`, and so on, with a 4-digit sequence starting at 0. The --dump-output-prefix and --dump-surface-option settings also apply to the numbered images.<br>Example: `ssp.exe --offline-dump "C:\SSP\ghost\myGhost" --dump-surface-list "0" --dump-animation 10 --dump-output-dir "C:\dump"`<br><br>Animations such as runonce and always run as they do in a normal dump, with the specified animation layered on top. Only the specified animation's own patterns are included in the sequence; advancing an always animation does not increase the number of images.<br>The dump ends when the specified animation reaches its last pattern (or completes one cycle for always). It also ends if the animation is stopped by another animation's stop command or by an exclusive setting.<br>Other animations started by start, alternativestart, or parallelstart are not included in the sequence. If the specified animation contains these patterns, a Warning is logged (output continues).<br>Start/stop-type patterns do not change the image and are not counted as frames in the sequence.<br>If the specified ID does not exist on a surface, or cannot be played because it is disabled by Dressup, blocked by an exclusive setting, or for another reason, a Warning is logged and only the usual single image is output for that surface.<br>The sequence is limited to 10000 images (through `_9999`). If this limit is reached, a Warning is logged and the sequence is cut short. |

### Offline tools

| Switch | Function |
|---|---|
| --offline-tool type \[2.9.01 and later\] | Starts in offline tool mode. Without starting a ghost, creates a NAR, update definition file, or archive from the folder specified by --target-dir, then exits immediately. No ghost events are triggered, and no window or message loop is created.<br>This performs the same operations as the Sakura Script commands `\![execute,createnar]` / `\![execute,createupdatedata]` / `\![execute,compressarchive]`, but the output location can be specified freely, without restrictions such as requiring a folder managed by SSP.<br>Specify one of the following types (case-insensitive).<br><br>nar: Creates a NAR file. Exclusions specified by nonar in `developer_options.txt`, .narignore, and similar settings are applied as in normal NAR creation. If install.txt is not present directly in the folder, the type and name are determined from descript.txt (or `ghost\master\descript.txt`), and install.txt is created in the target folder and included in the NAR. If the type and name cannot be determined, the operation fails.<br>updatedata: Creates an update definition file. If the --output filename ends in .dau, it uses the same format as updates2.dau; otherwise, it uses the updates.txt format. Only the specified file is created. No updates2.dau or updates.txt files are created or deleted directly in the target folder or in `ghost\master`. Exclusions specified by noupdate in `developer_options.txt`, .updateignore, and similar settings are applied as usual.<br>archive: Compresses the target folder as is. Exclusion settings such as .narignore are not read (hidden files and folders are not included). The format is determined by the --output extension: .7z produces a 7z archive; all other extensions produce a zip archive.<br><br>For all types, an existing output file is overwritten. If the output file is inside the target folder, the file itself is not included. The output folder must already exist.<br>Relative paths specified for --target-dir and --output are resolved relative to the current directory when SSP was started.<br><br>Exit codes:<br>0: Success<br>1: Invalid arguments (unknown type, missing --target-dir or --output, or --target-dir does not exist or is not a folder)<br>2: Creation failed (the output location is not writable, the NAR type and name cannot be determined, updatedata encountered an unreadable file or a directory structure that is too deep (more than 32 levels), etc.). A partially created file may remain after a failure.<br><br>Example: `ssp.exe --offline-tool nar --target-dir "C:\src\myGhost" --output "C:\out\myGhost.nar"`<br>Example: `ssp.exe --offline-tool updatedata --target-dir "C:\src\myGhost" --output "C:\out\updates2.dau"`<br>Example: `ssp.exe --offline-tool archive --target-dir "C:\src\data" --output "C:\out\data.7z" --password "pass"` |
| --target-dir folder path \[2.9.01 and later\] | Used with --offline-tool (required). Specifies the folder to process (the trailing \\ is optional). For a NAR or update definition file, specify the root folder of the ghost or other item (the folder containing descript.txt, install.txt, or the ghost folder). |
| --output file path \[2.9.01 and later\] | Used with --offline-tool (required). Specifies the path of the file to create. |
| --password password \[optional\] \[2.9.01 and later\] | Used with the nar or archive type of --offline-tool. Creates an AES-encrypted ZIP using the specified password (7z encryption is used for the 7z format). Ignored for updatedata.<br>Handle the password with care, as it remains visible on the command line. |

### Other

| Switch | Function |
|---|---|
| `initial_install.nar` | Although this is not a startup option, placing a NAR file named <strong>`initial_install.nar`</strong> in the same folder as ssp.exe causes it to be silently installed, overwriting any existing installation, when SSP starts (without a confirmation dialog). After installation, `initial_install.nar` is automatically deleted. This can be used when distributing SSP with ghosts or other items included. \[2.7.52 and later\] |
