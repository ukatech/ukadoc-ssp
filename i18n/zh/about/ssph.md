# 关于 SSPH（SSP Helper）

如果您在 SSP 文件夹或 Windows 界面中看到不熟悉的 `SSPH.exe`，感到不安，请参考本页。<br>
SSP 安装文件夹中的 `data\SSPH.exe` 是协助 SSP 完成工作的辅助程序「SSPH」。它是 SSP 本体（`ssp.exe`）附带的 SSP 组件，名称是 **SSP Helper** 的缩写。

SSPH 只在 SSP 本体等程序请求时启动，完成工作后会立即退出。平时不会运行。<br>
如果您在 Windows 用户账户控制（UAC）确认界面中看到「SSP Helper」或「SSPH.exe」而感到困惑，请参阅「[出现 UAC 确认界面时](#uacの確認画面が出るとき)」。

## 什么是 SSPH

- **文件位置**<br>
  位于 `(SSPのフォルダ)\data\SSPH.exe`。
- **文件属性**<br>
  在「详细信息」选项卡中，文件说明为「SSP Helper」，产品名称为「SSPH」，公司名称为「SSP BUGTRAQ」。
- **启动方式**<br>
  SSP 本体、安装程序或 Windows「已安装的应用」中的卸载操作会在指定工作内容后启动它。用户无需自行启动。即使不带参数启动，它也会直接退出，不执行任何操作。
- **显示内容**<br>
  根据工作内容，可能显示安装界面、进度窗口或确认消息。除此之外不会显示任何内容。
- **通信**<br>
  SSPH 自身只在安装程序中选择下载语言包时进行通信。语言包从其发布位置（GitHub）获取。

## SSPH 的工作

| 场景 | SSPH 的工作 | SSPH 引发的 UAC 确认界面 |
|---|---|---|
| NTP 时间同步 | 将电脑时钟修改为服务器时间 | 可能出现 |
| 安装 SSP | 显示安装界面，将 SSP 文件复制到安装位置 | 不会出现 |
| 更新 SSP 本体 | 等待 SSP 退出，用下载的更新覆盖文件，然后重新启动 SSP | 不会出现 |
| 获取人格的更新地址 | 查询人格的更新地址（`homeurl`） | 不会出现 |
| 卸载 SSP | 删除 SSP 文件夹和注册信息 | 不会出现 |

SSPH.exe 本身被设置为不请求管理员权限（`asInvoker`）。表中的「可能出现」是指仅在 NTP 时间同步时，SSP 本体会请求 Windows 以管理员权限启动 SSPH。

## 出现 UAC 确认界面时

修改电脑时钟需要 Windows 管理员权限。只有在进行 NTP 时间同步时，询问是否允许对设备进行更改的 UAC 确认界面中才会出现 SSPH。

### 出现的情况

- 通过右键菜单「功能→NTP 时间同步」让人格修正时钟时。仅选择菜单不会出现确认界面，服务器查询完成、人格实际修正时钟时才会出现。
- 人格自行开始 NTP 时间同步时。人格可以通过 Sakura Script 的 `\![executesntp]` 查询时间服务器。连接成功后会收到 `OnSNTPCompare` 事件通知，人格可以在其脚本中加入 `\6` 来修正时钟。因此，即使没有选择菜单，也可能在人格说话过程中出现确认界面。
- 在首选项中开启「自动执行时间同步」时。时钟会按指定间隔进行修正，每次都可能出现确认界面。在启用了 UAC 的管理员账户下正常启动 SSP 时，无法选择此设置（请参阅下方「不出现的情况」）。

### 如何查看确认界面

确认界面中的程序名称为「SSP Helper」或「SSPH.exe」。由于 SSPH.exe 没有数字签名，发布者显示为「未知」。具体界面因 Windows 版本而异。

仅凭发布者显示为「未知」，无法判断文件是否为正品。请通过界面中的「显示详细信息」确认以下内容。

- 程序位置是您使用的 SSP 文件夹中的 `data\SSPH.exe`
- 参数以 `time` 开头（这是执行 NTP 时间同步的标记）

详细信息的显示方式也因 Windows 版本而异。如果显示的文件不是您所熟悉的，请选择「否」。

### 选择「是」或「否」后

- **是**<br>
  SSPH 会将电脑时钟修改为从服务器获取的时间，然后退出。调整时也会加上确认界面打开期间经过的时间。SSPH 只会修改时钟。
- **否**<br>
  时钟不会改变，也不会影响 SSP 的其他功能。<br>
  但人格仍会收到「已修正时钟」的通知（`OnSNTPCorrect` 事件）。因此，即使时钟实际上没有改变，人格也可能说出时钟已修正的话。

### 不出现的情况

- 以管理员身份运行 SSP 时。SSP 本体会自行修改时钟，因此不会使用 SSPH，也不会出现确认界面。
- 在启用了 UAC 的管理员账户下正常启动 SSP 时。「自动执行时间同步」会变灰，无法选择，也不会自动出现确认界面。不过，如上所述，通过菜单或人格进行 NTP 时间同步时仍会出现确认界面。
- 使用没有管理员权限的标准用户账户时。可以选择「自动执行时间同步」。每次修正时钟时，可能会出现要求输入管理员密码的界面。

### 不想显示确认画面时

- 请不要使用NTP 时间同步。现在的Windows会自动同步时钟。
- 建议关闭“自动执行时钟同步”。不过，即使关闭此选项，人格执行NTP 时间同步时仍可能显示确认画面。
- 不建议仅为避免确认画面而以管理员身份运行SSP。因为这样会使SSP及其运行的所有人格都以管理员权限运行。

!!! tip "ヒント"

    在此处说明的操作之外的其他操作（安装、更新SSP本体、获取人格的更新地址、卸载）中，SSPH不会导致UAC确认画面出现。<br>
    如果在这些操作期间出现确认画面，请通过“显示详细信息”检查即将启动的文件。如果不认识该文件，请选择“否”。

## 各项操作的详细过程

### 安装SSP

运行SSP安装程序（自解压格式的exe）时，解压出的文件中的 `data\SSPH.exe` 会显示安装画面。启动安装程序后立即出现的“是否安装SSP？”确认提示由自解压部分显示，不是SSPH的画面。

- **安装位置**<br>
  如果已有SSP注册了文件关联，默认会填入该SSP的文件夹。否则默认为 `%LOCALAPPDATA%\Programs\SSP`。
- **可选项目**<br>
  包括开始菜单快捷方式、文件关联、桌面快捷方式和下载语言包。默认启用开始菜单快捷方式和文件关联，禁用桌面快捷方式。如果有适合您所用语言的语言包，则默认启用下载语言包。
- **受UAC保护的文件夹**<br>
  由于向 `Program Files` 或 `Windows` 文件夹下写入文件需要管理员权限，因此不能将其选为安装位置。请选择其他文件夹（例如：`C:\Users\ユーザー名\SSP`）。
- **包含SSP以外文件的文件夹**<br>
  如果选择的文件夹中已有文件，但没有 `ssp.exe` 和 `data\SSPH.exe`，则会显示确认画面。因为卸载时会删除文件夹中的所有数据。

安装完成后，会启动SSP。

### 更新SSP本体

SSP更新会在下载完成后立即应用，或者在下次启动SSP时应用预先下载并暂缓安装的更新。此时，SSP本体会将 `data\SSPH.exe` 复制为 `data\SSPH2.exe` 并启动，然后自行退出。由于SSP运行时无法覆盖本体文件，`SSPH2.exe` 会等待SSP退出后再开始操作。

`SSPH2.exe` 会显示“正在更新SSP...”窗口，并以覆盖方式解压下载的更新。接着，它会删除下载的文件并重新启动SSP，重新启动的SSP会删除 `SSPH2.exe`。

更新步骤请参阅“[更新SSP本体版本](../howto/verup.md)”。

### 获取人格的更新地址

当SSP需要知道人格的更新地址（`homeurl`）时，有时会让SSPH进行查找。SSPH按以下方式查找：

1. 读取人格的 `ghost\master` 文件夹中的词典文件等，查找 `homeurl` 的定义。
2. 如果找不到，则临时载入人格的SHIORI，获取 `homeurl` 的资源。

此操作在独立于SSP本体的进程中进行，最长等待2分钟。在此期间，即使打开对话框，也会自动关闭。<br>
SSPH运行期间，SSP本体会临时更改人格文件夹中可执行文件的名称（以 `perl`、`php`、`lisp` 开头的文件除外）（例如：将 `xxx.exe` 改为 `xxx_exe`）。在此期间，这些可执行文件将无法启动。SSPH结束后，会将其恢复为原名。

### 卸载SSP

启用文件关联时，Windows的“已安装的应用”（“程序和功能”）中会注册“SSP”。从这里删除时，SSPH会执行卸载。

1. 如果SSP正在运行，会提示先退出SSP，然后不执行任何操作便结束。
2. 显示“将删除人格等所有数据”的确认画面。选择“是”后继续。
3. 由于无法删除位于SSP文件夹中的SSPH自身，它会在临时文件夹中创建自身的副本（`%TEMP%\SSPHUninstall.exe`）并启动。
4. 副本会删除快捷方式、文件关联等注册信息，并删除SSP文件夹中的所有内容（会显示进度窗口）。
5. 最后，显示完成消息。

如果SSP文件夹位于驱动器根目录下（如 `C:\`），为避免删除驱动器中的内容，不会删除任何文件。<br>
SSP文件夹中的所有内容都会被删除，包括人格数据和备份。请提前将想要保留的内容移至其他位置。

`SSPHUninstall.exe` 会被安排在Windows重新启动时删除。如果无法安排删除，它可能会留在临时文件夹中。如果仍然存在，可以自行删除。

## 如何确认是否为正版

与 SSP 有关的 SSPH 只有以下三个文件名。

- `SSPH.exe`：位于 SSP 文件夹中的 `data` 文件夹内。运行安装程序时，运行的是解压后的临时文件夹中 `data` 文件夹内的文件。
- `SSPH2.exe`：仅在更新 SSP 主程序时，才会在同一个 `data` 文件夹中生成。
- `SSPHUninstall.exe`：卸载时会在 Windows 临时文件夹中生成。

名称或位置与上述不同的 SSPH 可能不属于 SSP。此外，属性中显示的信息可以被修改，因此请优先检查文件位置。<br>
如果不放心，可以将从 [SSP BUGTRAQ](ssp.md#ssp-bugtraq) 获取的 SSP 中的 `data\SSPH.exe` 与手头的文件进行比较。
